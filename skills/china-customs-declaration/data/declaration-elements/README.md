# 海关申报要素 Schema 文件

## 文件说明

本目录下的 JSON 文件是**申报要素 Schema**，用于描述不同 HS 编码前缀所对应的海关规范申报要素字段定义。这些文件为系统提供结构化数据，以便在商品归类分析中辅助生成标准化的申报要素表单。

## 重要声明

> **本数据为示例参考数据，非官方法定数据。**
>
> 具体申报要素以当年《中华人民共和国海关进出口商品涉税规范申报目录》及单一窗口系统为准。**不得**将本数据直接用于实际报关业务，所有数据在使用前须经官方渠道核实。

## HS 编码前缀匹配规则

当系统需要为某个 HS 商品编码查找申报要素时，按以下优先级逐级匹配：

1. **精确 10 位匹配** — 尝试匹配完整的 10 位 HS 编码
2. **8 位前缀匹配** — 取前 8 位匹配
3. **6 位前缀匹配** — 取前 6 位匹配（国际协调制度子目）
4. **4 位前缀匹配** — 取前 4 位匹配（国际协调制度章目）
5. **回退处理** — 以上均未匹配时，返回"当前未加载该HS编码的有效申报要素定义"，标记需通过单一窗口或当年规范申报目录核实

匹配采用最长前缀优先原则。例如，对于编码 `8528721200`，优先匹配 `852872` 的 schema（如存在），而非 `8528`。

## Schema 状态类型

每个 schema 文件包含 `verification_status` 字段，表示数据的核查状态：

| 状态 | 说明 |
|---|---|
| `official_confirmed` | 已与官方规范申报目录核对确认（当前无） |
| `internal_historical` | 内部历史项目积累数据，未经官方确认 |
| `example_only` | 示范示例数据，不应用于实际申报（当前所有数据） |
| `not_found` | 未找到匹配定义的占位标记（非独立文件） |

**当前所有 schema 均为 `example_only` 状态。**

## 字段结构说明

每个 schema 中的 `fields` 数组包含多个字段对象，各属性说明如下：

| 属性 | 类型 | 说明 |
|---|---|---|
| `name` | string | 申报要素的中文全称，如"品牌类型"、"用途"等 |
| `order` | number | 字段在表单中的显示顺序 |
| `required` | boolean | 是否必填 |
| `aliases` | string[] | 别名列表，用于匹配用户输入中的不同表述 |
| `source_keys` | string[] | 内部数据映射键名，用于程序化提取和映射 |
| `validation` | object | 验证规则，包含 `type`（数据类型）、`values`（枚举值列表）、`max_length`（最大长度）、`note`（填写说明） |

### validation.type 取值

| 类型 | 说明 |
|---|---|
| `enum` | 固定枚举值，从 `values` 中选择 |
| `text` | 自由文本输入，可选 `max_length` 限制 |
| `number` | 数值输入 |
| `date` | 日期格式 |

## 使用警告

1. **非官方数据** — 本目录下所有数据均标记为 `example_only`，未经官方核定
2. **年度变更** — 海关规范申报目录每年更新，本数据未绑定任何具体年度
3. **核对要求** — 任何使用场景下，必须通过单一窗口系统或当年规范申报目录进行核对
4. **不得伪造** — 对于未找到匹配的 HS 编码，不得伪造法定申报要素字段
5. **HS编码子目差异** — 同一 4 位前缀下的不同 8/10 位子目，申报要素可能存在差异，本目录仅提供基础参考

## 维护

- 新增 schema 时，同时更新 `schema.json` 注册文件
- 所有新数据须明确标注来源和核查状态
- 如无法确认官方数据，必须标记为 `example_only`
